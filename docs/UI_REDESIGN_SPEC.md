# Career OS UI redesign — Paper Intelligence

版本：2026.08 · 目标画布：1440 × 900 · 实现环境：Streamlit 1.60+

## 1. 全局概念与关键词

设计概念为 **Paper Intelligence / 纸上智能**：把个人求职工具理解为一份持续生长的编辑部档案，而不是企业 SaaS 控制台。页面以纸张、目录、批注、编号和证据为视觉隐喻，让 AI 的作用像一名克制的研究助理。

关键词：编辑式、纸感、证据优先、低饱和、强层级、非对称、安静反馈、可追溯。

- MUUUUU.ORG：大留白、低饱和纸色、紧凑字距、大标题。
- Siteinspire：01—09 编号信息架构、稳定网格、清晰分类。
- Godly / Awwwards：4.8rem 标题、局部 5:3 非对称、横向张力。
- Motion：仅为进入、按下、加载和状态确认提供 120—240ms 反馈。

## 2. 1440 × 900 桌面端方案

基础结构：240px 左侧系统栏 + 1px 分隔线 + 最大 1280px 主内容区。主内容左右安全边距 32px，实际常用内容宽度约 1120px。首屏顶部为 36px 分类导航，其下留 52px；页面标题占 200—250px 高度，业务内容从约 y=330 开始。

- 左侧：品牌、06—09 系统工具、AI 连接状态和隐私设置。
- 顶部：01—05 主工作流，当前项为墨黑底；其余项无卡片边框。
- 页首：等宽英文编号眉题 + 56—76px 中文标题 + 一行说明。
- 内容：12 列网格，常用比例 6:6、7:5、8:4；同层最多 4 个指标。
- 表格：占满内容区，固定关键列；筛选与行动条独立置于表格上方。

四个优先页面：

1. 岗位发现：连接和搜索为准备区；发现箱为主画布。筛选后先显示 4 个决策指标，再显示宽表和岗位详情。
2. 岗位分析：四段纵向证据流。档案摘要 → 简历版本 → JD → 条件校对 → 评分结果，避免把长表单压成控制台。
3. 投递台账：首屏显示总量、待投递、进行中；第二层为阶段视图与搜索；主表固定公司、职位，事件历史在下方。
4. 复盘看板：7:5 非对称首行，左侧转化漏斗，右侧今日行动；第二行 5:7，为公司类型和简历版本效果。

## 3. Design tokens

### 颜色

| Token | 值 | 用途 |
|---|---:|---|
| Paper | `#F4F1EA` | 页面背景 |
| Surface | `#FAF8F3` | 卡片与指标底 |
| Ink | `#191916` | 标题、选中导航、主按钮 |
| Muted | `#716F68` | 辅助文字、元信息 |
| Line | `#D8D3C8` | 表格、输入框、卡片边框 |
| Vermilion | `#C84B31` | 唯一品牌强调、关键动作 |
| Forest | `#1F4C43` | 成功与第二数据系列 |
| Blue gray | `#41627E` | 中性信息状态 |
| Amber | `#B06B35` | 等待、需跟进 |

禁止大面积渐变、霓虹、透明玻璃层和装饰性色块。语义色不单独承担信息，必须同时有文字或图标。

### 字体

- 正文：Inter / SF Pro Text / PingFang SC / Microsoft YaHei，15px，400。
- 页面标题：同一无衬线字体，56—76px，620，字距 `-0.065em`。
- H2 / H3：29 / 22px，620；组件标题 17px，600。
- 编号和元信息：SF Mono / Consolas，11—12px，650，字距 `0.12em`。
- 长文本行高 1.75；表格 1.45；单行正文建议不超过 72 个中文字符。

### 几何与层级

- 间距基数 4px；常用 8 / 12 / 16 / 24 / 32 / 48 / 64。
- 页面区块间 60px；标题与说明 12px；表单字段 16px。
- 输入框与按钮圆角 4px；表格 6px；普通容器 6px；徽标使用 full radius。
- 默认边框 1px `#D8D3C8`；关键区块顶部使用 1px Ink。
- 阴影默认无；仅浮层允许 `0 12px 32px rgba(25,25,22,.08)`。

## 4. 组件规范

- 导航：主流程横向编号，系统页放左栏；当前项墨黑底，hover 为暖灰底。
- 按钮：主按钮使用朱砂底/白字；次按钮纸色/墨色边框；tertiary 无底。按钮文本使用动词开头。
- 表格：表头暖灰、6px 圆角、关键列固定；数字右对齐，状态和建议不依赖颜色；编辑只开放必要列。
- 输入框：默认纸白底、1px 线框；placeholder 使用 Muted；聚焦显示品牌色边框，不使用外发光。
- 状态标签：小尺寸 badge，成功 Forest、等待 Amber、错误 Vermilion、信息 Blue gray。
- 提示条：只用于会影响下一步的重要信息；普通解释使用 caption。成功操作优先 toast。
- 卡片：仅在需要表达同一上下文时使用，避免每个区块都卡片化。无装饰阴影。
- 指标：最多 4 个并列，标签 12px，数值 32px；指标必须支持决策，而非装饰。

## 5. 九个页面布局

### 01 岗位发现

连接平台折叠为次要设置；搜索方案为单一表单，平台使用 pills，关键词占主列，扫描限制占次列。发现箱提供平台/状态筛选、筛选结果、高匹配、候选清单、已进台账四指标；宽表下方只展示当前选中岗位的来源、原文、评分证据和明确行动。

### 02 岗位分析

求职档案作为可信上下文条；简历版本选择保持单列。JD 输入为大文本画布，提取后进入三列结构化校对。资格条件和本岗位安排使用 expander 管理长表单。结果先展示分数、门槛和建议，再展开证据，最后提供进入投递计划的唯一主行动。

### 03 求职材料生成

顶部说明使用的岗位分析快照；材料类型用 tabs 或 segmented control。正文采用可复制长文本区，事实证据和风险提示放右侧窄列。生成、重写、复制、保存分别使用主、次、tertiary 行动层级。

### 04 投递台账

三项管线指标后提供阶段视图和搜索。主表保持横向滚动与固定公司/职位列；保存和下载位于表格下方同一行动条。事件历史作为第二章节，撤销错误事件折叠处理。

### 05 复盘看板

范围切换在标题下方。首行指标给出总数、投递、面试和 Offer 转化。转化漏斗与今日行动 7:5；公司类型与简历版本效果 5:7。图表最多两种强调色，弱化网格。

### 06 评分规则

先说明“专业匹配”和“资格门槛”分离原则；维度权重为静态表；版本说明、校准规则和边界情况分别折叠，避免像配置后台。

### 07 简历库

简历版本与求职档案为两个 peer tabs。版本列表强调不可变、默认版本和分析次数；上传为明确主行动。档案编辑按事实、可用时间、偏好分组，并通过单次表单提交。

### 08 分析历史

上方为可排序历史表，下方为选中记录详情。结果摘要三指标；简历、JD、评分快照三 tabs。历史记录必须明确显示模型、规则和版本号。

### 09 同步中心

连接状态先于设置；邮箱连接使用折叠区。待确认、已确认、已忽略作为 review tabs。所有自动识别结果同时显示置信度、关联岗位和明确确认动作。

## 6. 状态矩阵

| 状态 | 表现 |
|---|---|
| 默认 | Paper / Surface 背景，1px Line 边框 |
| 悬停 | 背景向暖灰变化；按钮不位移 |
| 选中 | Ink 底或品牌色边框，同时保留文字/图标 |
| 禁用 | 40% 不透明度，移除阴影和按压反馈，保留原因提示 |
| 加载 | 预留原尺寸 skeleton；长任务使用可折叠 status 显示步骤 |
| 成功 | Forest badge 或短 toast；不会改变布局高度 |
| 错误 | Vermilion 提示条，提供原因和下一步；阻断时才常驻 |
| 空状态 | 单个线性图标、短标题、一句解释、一个主行动 |

## 7. 动效

- 页面进入：240ms，`cubic-bezier(.22,.8,.28,1)`，透明度 0→1，Y 7px→0。
- hover：150—160ms，`ease-out`，仅背景、边框、文字颜色。
- 按下：120ms，`cubic-bezier(.2,.8,.2,1)`，缩放至 0.985。
- 状态成功：160ms 颜色切换；toast 使用 Streamlit 原生生命周期。
- 加载：使用 `st.skeleton` 或 `st.status`；不使用无限装饰动画。
- 只在页面切换、选择切换、异步加载、保存完成和错误出现时触发。
- 必须支持 `prefers-reduced-motion`，将时长降为 0.01ms。

## 9. Streamlit 原生与自定义组件边界

优先原生：`st.navigation` / `st.page_link`、`st.pills`、`st.segmented_control`、`st.form`、`st.dataframe`、`st.data_editor`、`st.metric`、`st.badge`、`st.status`、`st.skeleton`、`st.toast`、`st.dialog`、Altair 图表。主题使用 `.streamlit/config.toml`，少量稳定 CSS 只处理导航、标题、间距和动画。

需要自定义组件 v2 才值得做的效果：跨表格拖拽岗位阶段、可缩放关系图、复杂时间线直接编辑、带键盘漫游的命令面板、无需 rerun 的多选批量动作。它们不是当前版本的必要条件；若实现，应独立封装并通过事件把最小数据返回 Python，不应替换原生表格和表单。

不建议实现：滚动视差、磁吸按钮、跟随光标、全屏页面转场、WebGL 背景和纯装饰 marquee。它们会削弱长文本和数据操作体验，也不符合本工具的可信感。
